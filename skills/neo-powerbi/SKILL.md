# neo-powerbi：让 AI 直接在 Power BI 里干活的规矩

这份 skill 不教 Power BI 怎么用，只规定**怎么干活**。微软官方的 `semantic-model-authoring`、`powerbi-report-cli` 管「能做什么」，这里管「按什么规矩做」。两者一起装效果最好。

## 1. 先连上，再只读看一遍

1. 先问清楚要连哪个文件，再连：`Connect to '<文件名>' in Power BI Desktop`。文件名不确定就先列出当前打开的 Power BI Desktop 实例，让用户选，不要猜。
2. 连上后**先只读**：列出所有表、列、度量值、关系，用一张表汇报给用户。
3. 用户要的东西涉及哪些表和字段，用这一步看到的真实名字。**模型里没有的字段不许编**；缺什么就直接说缺什么。

## 2. 动手前

- 改动超过 3 个对象，或要删除、重命名任何东西：先列出计划（新增 / 修改 / 删除 各几个，叫什么），等用户说「可以」再动手。
- 提醒用户先存一份副本（另存为 `<原名>_备份_<日期>.pbix`），或确认文件已经在 git 里。没确认就只做新增，不做删除和重命名。
- 能用事务就用事务：一批改动要么全成，要么全回滚。

## 3. 命名和格式

**度量值**
- 中文名，说清楚是什么：`销售额`、`销售额 同比`、`销售额 年累计`、`销售额 占比`。不用 `Measure 1`、`m_sales_yoy`。
- 放进显示文件夹：`01 基础`、`02 时间对比`、`03 占比排名`、`99 辅助`。
- 每个度量值写一句说明（Description）：算的是什么、分母是什么。
- 格式字符串必须设：金额 `#,0`，百分比 `0.0%`，同比/环比 `+0.0%;-0.0%;0.0%`。

**表和列**
- 事实表、维度表名字一眼能看出是什么：`销售明细`、`日期`、`产品`。
- 不给用户看的辅助列设为隐藏。
- 有时间分析就必须有一张连续的日期表，并标记为日期表；不要用事实表里的日期列直接做时间智能。

**常用写法（按这个模板，不要每次重新发明）**

```dax
销售额 同比 =
VAR 本期 = [销售额]
VAR 去年同期 = CALCULATE ( [销售额], SAMEPERIODLASTYEAR ( '日期'[日期] ) )
RETURN DIVIDE ( 本期 - 去年同期, 去年同期 )

销售额 年累计 = TOTALYTD ( [销售额], '日期'[日期] )

销售额 占比 =
DIVIDE ( [销售额], CALCULATE ( [销售额], ALLSELECTED ( '产品'[类别] ) ) )
```

- 除法一律用 `DIVIDE`，不用 `/`。
- 用 `VAR` 把中间结果起名，别写一长串嵌套。
- 遇到「总计 ≠ 各行相加」：先跟用户说明总计行是按整体重新算的，再问用户想要哪种总计，不要擅自改成 `SUMX`。

## 4. 配色和报表

- 主题优先用仓库 `themes/` 里的三套：`oat-latte`（月报、复盘）、`forest-gold`（大屏、暗色）、`mist-blue`（汇报）。
- 第 1 个颜色留给最重要的数；对比数（去年、目标）用第 2 个颜色或虚线。
- 排名图只用一个颜色，第一名用主色，其他用同色调浅色。
- 占比图最多 6 种颜色，再多合并成「其他」。
- 页面底色不用纯白，卡片用白色。
- 涨跌不只靠红绿，加 ▲▼ 符号。
- 一个图只有一个纵轴，不做双轴图。

## 5. 改完必须核数

- 每新增或修改一个度量值，用 DAX 查询算一遍，把结果给用户看，例如：

```dax
EVALUATE
SUMMARIZECOLUMNS ( '日期'[年], "销售额", [销售额], "同比", [销售额 同比] )
```

- 至少核一处能手算的数（比如某一年的合计），对不上就停下来说明，不要继续往下做。

## 6. 汇报格式

每轮做完，用这个格式告诉用户：

```
✅ 新增：3 个度量值（销售额 同比、销售额 年累计、销售额 占比）→ 文件夹「02 时间对比」
✏️ 修改：1 个（销售额：格式改成 #,0）
🗑️ 删除：无
🔎 核数：2025 年销售额 1,234,567，与源表合计一致
⚠️ 需要你决定：……
```

## 7. 不做的事

- 不碰用户没提到的表和度量值。
- 不在没确认的情况下删除、重命名、改关系方向。
- 演示、截图、录屏只用示例数据或公开数据（仓库 `sample-data/`），不打开工作文件。
